Contract first · with a coding agent

Build a data product with AI.

No one writes the pipeline by hand anymore. A coding agent does. What makes the difference is what you feed it: a data contract that says what to build, skills that say how, and a data marketplace with the data to build on.

The idea

The agent is a commodity.
The inputs are what matter.

With all three inputs in place, the instruction to the agent is a one-liner: implement it. The finished data product goes back into the marketplace, and the next one can stand on its shoulders.

Input 1

Data contract

the what

The interface specification in the Open Data Contract Standard, linked to a data product and to the business ontology.
Input 2

Skills

the how

Your company's patterns and conventions, in a Git repository of skills, templates, and hooks. You stay in control of how it is built.
Input 3

Data marketplace

the data to build on

Which data products exist, what their data means, and access to actually query it. Data products build on data products.
Before any YAML

It starts with a conversation.
Not with the data.

Get the people who need the data into a room. Put the Data Product Canvas on the wall and fill it from the right: the business case drives the interface, and the interface drives the sources.

Input 1 · the what

The data contract

A YAML file in the Open Data Contract Standard that sits next to a dataset and states everything guaranteed about it. Keep scrolling, it writes itself.

          Contract + semantics + data product
          
Every part is an open standard.

          
The building block uses the Open Data Product Standard, the interface the Open Data Contract Standard, and the meaning Apache Ossie. None of it depends on a tool. It is just standards, YAML, and structure.

apiVersion: v1.0.0kind: DataProductid: slow-selling-brandsstatus: draftoutputPorts:  - name: slow_selling_brands    version: 1.0.0    contractId: slow-selling-brands   # the contract above

with shelf_warmers as (select * from {{ ref('shelf_warmers') }}),
     articles      as (select * from {{ ref('articles_latest') }})

select
  a.brand_name::varchar         as brand,
  count(*)::integer            as slow_selling_products,
  max(sw.last_sold_date)::date as latest_sold_date
from shelf_warmers sw
join articles a on sw.sku = a.sku   -- same concept in the semantics
group by a.brand_name

          
CTEs over shelf warmers and articles, joined on SKU, grouped by brand, cast to the contract's types. If the join columns had different names, it would still work, because both point to the same concept. Simplified.

          Now let's change it
          
Iterate by changing the what.

          
Creating a data product happens once. Changing it happens all the time, and it works the same way: change the contract first, then say "implement it" again. A slow-selling brand with one cheap product can be ignored. An important brand with a lot of stock cannot.

          Data-first or contract-first?
          
Two paths to a data product.

          
Data engineers have always started with the data: extract, explore, build. It is creative, fast, and grounded in reality. But exploration alone is not a product. Flip the switch.

DocumentationIs TX021 the order date or the payment time?

          From the audience
          
But can you trust it?

        

        

          
Agents are non-deterministic. How can you trust the data product?
With feedback loops built on deterministic tools. Tests must be green, the linter must be happy, it must conform to the skills and the security guidelines. If not, it iterates. That harness makes hallucination "almost go away. It's not completely gone, but it's good enough, and better than humans."

          
If building is this cheap, won't the number of data products explode?
The bottleneck is still humans. Building is cheap now. Deciding what to build and who owns it is where humans decide. And changes still need a process: a stable interface, a guaranteed lifetime, an upgrade path for breaking changes. "Let's not get rid of the humans."
